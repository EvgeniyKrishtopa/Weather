# I18n And Locale

The app does not currently have a full translation/i18n framework. Existing
locale behavior is limited to country/default-location handling and English
sorting/display conventions.

## Current Locale Behavior

- `src/utils/localeCountry` detects a default country from browser locale when
  possible.
- `DEFAULT_COUNTRY_ISO` is the fallback country.
- Countries and cities are sorted with English locale comparison.
- Country options use ISO-2 country codes.
- Reverse geocoding returns ISO-2 country codes from OpenWeather.

## Guidelines

- Do not introduce an i18n library without a concrete requirement.
- Keep country ISO validation centralized around existing constants and type
  guards.
- Preserve default-country and geolocation behavior when changing form startup
  flows.
- If adding translations later, keep user-facing strings close to UI domains or
  introduce a deliberate localization module instead of scattering ad hoc maps.
